# 同期・オフライン仕様

## 方針
収集体験は「端末先行 + Supabase同期」。通信障害を理由に訪問そのものを失わせない。

## CollectionHistoryService
訪問RPCが通信・認証等で失敗した場合、元のvisited_at、位置情報、client_visit_id等をSharedPreferencesの保留キューへ保存し、後で再送する。サーバーが恒久拒否を示す特定エラーは無限再送対象にしない。

## キャッシュ
獲得履歴・スタンプ状態・NEXT/推奨ルート等は用途別Serviceでローカル永続化される。旧キーからユーザーID付きキーへの移行処理を持つ箇所がある。

## 起動時
StartupCoordinatorのcritical段階で同期を開始し、描画後にpending結果・クラウド履歴を適用する。UI初期表示をネットワーク処理で過度に塞がない。

## 原則
- 同一訪問の再送はclient_visit_id等で冪等に扱う。
- ローカルキャッシュはクラウド正本と競合し得るため、単純上書きよりマージ方針を優先。
- イベント切替時は別イベントの収集状態を混ぜない。
- キュー形式変更時は既存ユーザーの移行を設計する。
